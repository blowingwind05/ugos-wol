## gzip 旧资源的真实根因

2026-11-12，已在登录后的真实 UGOS 网页中复现：

- 新 HTML 已引用 `app.js?v=fc7b267dd172`，但浏览器实际执行旧扫描界面。
- 对实际 `10002` 应用端口和 `9443/com.local.wol/` 分别请求，`Accept-Encoding: identity` 返回新版脚本（SHA256 `fc7b267dd1727a323580e13f3d82d8513c56bbeeb7ecb3cc4468569e0c3a9fd3`）；请求 gzip 后，解压内容却是旧脚本（SHA256 `8870a770038e3ca6f7d6a3e6d5f4030329a77a95e1dbc8eccd749e31b48a1f48`）。
- NAS 应用目录残留旧 `app.js.gz` 和 `style.css.gz`；只更新原文件、查询参数或安装包构建号，不能修复这个压缩表示不一致问题。先前归因于浏览器缓存与构建号不充分。
- 构建现为稳定文件、带内容指纹的文件名及对应 `.gz` 同步生成；包含入口页压缩副本。构建检查解压后逐字节一致，并覆盖存在旧 `.gz` 时的更新场景。
- 4 项构建检查、图标缓存浏览器检查、17 项扫描界面检查及后台 race 检查通过。
- 官方 ugcli 生成双架构 `0.2.4.0004`，应用显示版本仍为 `0.2.4`。通过真实 UGOS 应用中心将 amd64 NAS 从 `0003` 更新至 `0004`，安装成功。
- 在登录后的 Chrome 桌面实际打开应用并扫描：7 条结果全部使用显示器图标，6 条显示设备名；未公布名称的记录回退到 IP/MAC。入口页、脚本、样式及两个 SVG 的实际 gzip 响应解压内容均与本地构建 SHA256 一致。脱敏记录见 [NAS gzip 实测](NAS-GZIP-VALIDATION.json)。本次未新增设备、发送唤醒包或修改已有设备配置。
- ARM64 实机及移动客户端未纳入这次验证。

## 自动检查

在 `backend/` 运行 `go test ./...`。检查范围包括：

- 标准102字节魔术包的内容及真实 UDP 回环接收。
- MAC 格式、单播地址、重复设备和请求内容限制。
- 设备增删改、持久化、旧配置加载与损坏配置保护。
- 发送冷却、部分/完全发送失败及记录写入失败时的真实反馈。
- 每次请求的管理员校验、伪造身份拒绝、不同管理员操作归属。
- 缺少角色字段时的本地管理员组验证及失败关闭。
- 普通网口、聚合、VLAN、LAN 网桥和容器接口的筛选。
- 静态页面资源与 JSON 请求大小限制。

这些检查使用临时数据目录、模拟发送函数或本机回环接口，不应向真实目标设备发送测试唤醒包。

## 架构与实机验证

使用 Python 3 运行 `python3 scripts/tests/test_packaging.py`，可离线检查双架构/单架构选择、目标文件防覆盖、缺少输入时禁止部分导出，以及非法架构拒绝。此检查使用隔离的模拟工具和临时载荷，不生成真实 UPK。

`bash scripts/build-binaries.sh` 分别交叉编译 `amd64` 与 `arm64`。应核对 ELF 架构，并分别使用匹配的硬件验证：

1. 应用中心安装/更新、启用、停止及数据保留。
2. 真实 UGOS 登录令牌、管理员/普通账号与角色字段兼容。
3. NAS 网口、LAN 网桥、聚合和多网段环境的识别。
4. 真实广播数据包、目标设备支持的电源状态及唤醒结果。
5. 绿联远程访问和移动客户端中的操作。

现有实机记录集中在 amd64；ARM64 的交叉编译不能替代实机安装和唤醒测试。跨设备唤醒能力以硬件、驱动和广播网络条件为准。

## 自动检查

在 `backend/` 运行 `go test ./...`。检查范围包括：

- 标准102字节魔术包的内容及真实 UDP 回环接收。
- MAC 格式、单播地址、重复设备和请求内容限制。
- 设备增删改、持久化、旧配置加载与损坏配置保护。
- 发送冷却、部分/完全发送失败及记录写入失败时的真实反馈。
- 每次请求的管理员校验、伪造身份拒绝、不同管理员操作归属。
- 缺少角色字段时的本地管理员组验证及失败关闭。
- 普通网口、聚合、VLAN、LAN 网桥和容器接口的筛选。
- 静态页面资源与 JSON 请求大小限制。

这些检查使用临时数据目录、模拟发送函数或本机回环接口，不应向真实目标设备发送测试唤醒包。

## 界面检查

使用模拟 UGOS SDK 与 API 检查以下行为，不在生产前端加入免认证入口：

- 登录、身份过期、普通账号拒绝、重试与连接失败提示。
- 通用设备卡片、设备管理、发送反馈、操作人及错误记录。
- 用户输入转义、重复点击防护、过期或缺失的发送接口。
- 桌面与手机布局，以及长名称和不同屏幕宽度下的显示。

旧版界面检查结果保留为本目录中的版本化 JSON。它们记录对应版本的检查范围，不能代替当前版本或实际 UGOS 窗口验证。

## 架构与实机验证

使用 Python 3 运行 `python3 scripts/tests/test_packaging.py`，可离线检查双架构/单架构选择、目标文件防覆盖、缺少输入时禁止部分导出，以及非法架构拒绝。此检查使用隔离的模拟工具和临时载荷，不生成真实 UPK。

`bash scripts/build-binaries.sh` 分别交叉编译 `amd64` 与 `arm64`。应核对 ELF 架构，并分别使用匹配的硬件验证：

1. 应用中心安装/更新、启用、停止及数据保留。
2. 真实 UGOS 登录令牌、管理员/普通账号与角色字段兼容。
3. NAS 网口、LAN 网桥、聚合和多网段环境的识别。
4. 真实广播数据包、目标设备支持的电源状态及唤醒结果。
5. 绿联远程访问和移动客户端中的操作。

现有实机记录集中在 amd64；ARM64 的交叉编译不能替代实机安装和唤醒测试。跨设备唤醒能力以硬件、驱动和广播网络条件为准。
